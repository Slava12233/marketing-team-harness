# /sync: close the session, the vault and the checklist

Project rules (`CLAUDE.md`) and the vault contract (`memory/README.md`, "who writes what", `/sync`) win on conflict; the `memory-update` skill is the procedure for every note written here. No PII, no secrets (names only), counts only, absolute dates. Light node scripts run with `timeout 120` first where the shell has it, one at a time, in the foreground.

**Output:** vault notes under `memory/`, the flight's plan file, `checklist.md`, the generated files (`memory/HOT.md`, `memory/INDEX.md`, HOME's block, `memory/capabilities/*`, `dashboard/state.json`), the setup progress page; `CLAUDE.md` only for a durable rule; `config/*.md` only for a company or account fact that changed. **Language:** notes, plan and checklist text in English; the Inbox answers, the weekly review and the closing message in the chat language from `config/operator.md`; money in the account currency from `config/accounts.md`.

## Procedure
1. **Collect the facts of this session**, each with its evidence: state changes (object ids, statuses, budgets, schedules, uploads with image hashes and video ids), decisions the Owner made (their words, quoted), requests filed to the product team (file names), reports written, open items and their owners, timings learned (review durations, platform behaviour). Start from today's session note `memory/sessions/YYYY-MM/YYYY-MM-DD.md`. A fact that cannot be verified is written as "unverified".
2. **One live read** of every changed Meta object (`ads_get_ad_entities`, `ads_get_errors`) before anything is recorded; the record says what the read showed, not what was requested. When anything is ACTIVE, the same read takes today's and this week's spend and the live daily budgets, so they can be held against the caps in `config/goals.md` (the logic of `health` check 15).
3. **Merge `memory/inbox/proposals.md`.** For each line a sub-agent appended: grep `memory/INDEX.md`, then either (a) make it a learning note from `memory/templates/learning.md` (durable Meta behaviour under `memory/learnings/meta-platform/` plus its link in `memory/maps/build.md`), (b) apply it as a correction (a superseding note, or a rewrite of an entity note's `## Current state` with a `## Log` line), or (c) decline it with a one-line reason appended under it, which goes into today's session note. Then empty the file below its frontmatter and heading. A `## Consolidation YYYY-MM-DD` block from `/consolidate` that the main session has not applied yet stays in the file and is named in the closing message.
4. **Answer `memory/inbox/owner.md`.** Every open line gets an indented `↳` bullet under it, in the chat language: done (with the note it was filed to, `[[note]]`), needs your go (the cost stated; never acted on from the Inbox), or filed to `[[note]]`. Answered lines with their `↳` bullets move to the answered section. The Owner's own words are never edited.
5. **Vault notes.** Check that every state change of the session already rewrote its entity note's `## Current state` and appended to its `## Log`, and fix what is missing; `memory/state/current.md` true now (the campaigns table re-verified with step 2's read, `as_of` = that read) and its next actions rewritten as numbered first actions for the next session; every id from the session in its campaign or flight note and in the plan file; every ruling a decision note; every finding a learning note; a company or account fact that changed corrected in `config/*.md` and its `memory/business/` note together. Then close today's session note with its `## Close` block: asked, done, live now (per day in the account currency, and the cap), open (with owners), requests filed, ids; set its `status: done`.
6. **Weekly review.** On the last working day of the week (working days in `config/operator.md`), if `memory/reviews/YYYY-Www.md` (ISO week) does not exist because `/next-round` did not run, write it from `memory/templates/review-he.md` or `memory/templates/review-en.md` (the chat language's; the English one, translated, for any other language), in the chat language, every figure with `as_of` and `source`.
7. **The go checklist** (`checklist.md`, repo root).
   - Read the table first.
   - Update only the rows the session established a fact about: `status` (open / blocked / done / n/a), `note` (one or two sentences, counts and ids allowed, starting with the date and time), `updated` (the date). An item owned by the Owner, the Operator or the Product team is never set to done by the harness; it gets a note. Items the harness owns may be set to done with the evidence in the note.
   - Add a new row for a gate the session discovered (next free id, owner, status `open`).
   - Append one line under `## Sync log`: `- YYYY-MM-DD HH:MM <timezone>: <what changed, what is open, what is next>` (at most 400 characters). A second sync the same day gets its own line. When spend above a cap in `config/goals.md` was observed this session (step 2's read, a `/morning` or a `/health` run), the line names it: the cap, the spend and its period, and whether the Owner paused.
   - Never rewrite or delete an earlier Sync log line or a teammate's note; add a dated line instead. If `checklist.md` is missing, recreate it with the shape in `docs/TEMPLATE-SPEC.md` §9 from `memory/state/current.md` and the open items, and say so in the closing message.
8. **Generate.** `timeout 120 node memory/tools/build-capabilities.mjs`, then `timeout 120 node memory/tools/build-hot.mjs --by sync`: HOT, INDEX, HOME's generated block and `dashboard/state.json` (the control-room board, keys fixed by `docs/TEMPLATE-SPEC.md` §9; the first open task is the next session's first action; `money.caps` copied from the caps table of `config/goals.md`, the Owner's limits, with `memory/business/goals.md` as the fallback while `config/goals.md` holds placeholders; `money.dailySpend` only from a live read, null when there is none). When `memory/business/goals.md` disagrees with `config/goals.md`, `config/goals.md` wins: correct the note in the same run. Never hand-edit what the tools write; if a tool fails, say so in the closing message and leave the old files in place. Then regenerate the setup progress page with `node dashboard/setup-page.mjs` (it reads `checklist.md`, the console-steps table of `config/accounts.md` and `dashboard/state.json`; the Owner's open steps show there as "your turn").
9. **Lint.** `timeout 120 node memory/tools/lint.mjs`. A FAIL (a secret or PII shape, a dead link, a cap breach, a hand-edited generated note, an edited dated note) blocks the close: fix the note, rerun the generators if a source changed, and lint again until it exits 0. A cap breach is fixed with `/consolidate`. Warnings are listed in the closing message.
10. **Commit, local only, and only in a git repository.** `git rev-parse --is-inside-work-tree` first: if the folder is not a git repository (a buyer's folder often is not), skip this step and say so in one line of the closing message. Otherwise `git check-ignore -q .env` must succeed (if `.env` is not ignored, skip the commit and say so: a secret would be committed), then `git add -A && git commit -m "<the session's one-line subject>"`. Never push; a remote and a push are the Owner's word only.
11. **Closing message to the Owner**, at most 15 lines, in the chat language: what changed (with ids), what is live and what it costs (per day in the account currency and the cap; "nothing live, 0" when so), any cap in `config/goals.md` crossed or at 80 % or more, what is open and who owns it, the Inbox lines answered and the proposals merged or declined (counts), the lint result in one line, the commit (its subject, or "not a git repository: no commit"), the first action for the next session, the paths of the day's report files, today's session note and `checklist.md`.

## Rules
- Reports are written once; a correction is a new dated file or a dated line, never an edit of a read report. Dated vault notes (learnings, decisions) are superseded, never edited.
- A sync never activates, pauses, deletes or changes delivery; it records. A pause the Owner asked for in chat is executed by the main session before the sync, then recorded. A spend-affecting Inbox line becomes "Needs the Owner's go", never an action.
- One writer: the main session writes the canonical notes; a delegated `harness-librarian` writes only `memory/inbox/proposals.md` and the `memory/archive/` moves the main session ordered.
- Relative dates become absolute; times carry the timezone from `config/operator.md` when they matter.
- Never write a number into a note, the checklist or the board that a live read did not give; the one exception is the board's `money.caps`, the Owner's numbers from `config/goals.md`.
