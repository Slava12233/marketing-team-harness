# /health: is the harness working? (read-only)

Every check is a read. A red item gets a one-line "what to do" and, when the fix is a click or a console step, it is the Owner's. Project rules (`CLAUDE.md`) win on conflict.

**Output:** one table in the terminal (at most 30 lines); when run from `/morning` it becomes section 1 of that report; when any item is red and the run is stand-alone, also `reports/YYYY-MM-DD-health.md`. **Language:** the report file in English; the terminal lines and the "what to do" lines in the chat language from `config/operator.md` (check names and ids stay as they are).

**`/health --keys` (the keys view; chapter A10 of `/connect`, whose console chapters are `onboard`).** Only the rows of the onboarding's Part A, in this order, printed as the keys table: 28 this copy, 26 desktop app, 27 Chrome + extension, 1 MCP, 2 login, 5 pixel, 13 upload token, 20 Graph token, 29 Google login, 25 credential map, 8 fal, 18 hooks, 19 Obsidian. The same reads and colours; no report file and no `health.run` mark. Every row green, or n/a by the Owner's word (fal skipped, no website) → `node dashboard/setup-page.mjs --mark keys.table=done`; otherwise the first row that is not names the click and the mark stays. Rows 26 and 27 also mark `app.desktop` and `chrome.extension` (`done` when green, `todo` when red) on every run, keys view or full.

**Platforms.** `config/operator.md` names them (`**Platforms:**` Meta, Google, or both; unset means both are checked). The Meta rows (2–5, 13, 20, the Meta names of 25) read **n/a** "not a platform of this company" when Meta is left out; the Google rows (29, 30, the Google names of 25) read n/a when Google is.

Optional connections that are not set up read **n/a** with the reason, never red: fal (only when the fal MCP is loaded), the preview site (only when a plan names one), the product team's open-items file (only when `config/product-team.md` names one), the lead webhook (only when `config/accounts.md` holds a `lead_webhook_url`; by default leads are read in Leads Center). A company without a website is the same: `pixel_id` = `none (no website)` makes check 5 n/a, and a destination row of `none` makes check 6 n/a.

## Before the checks
Read `memory/maps/build.md` and the `memory/learnings/meta-platform/` notes it lists (vault contract `memory/README.md`, "who reads what": `health` reads the build map before any check of the account), then `memory/state/current.md` for the ids, statuses and counts that checks 3, 4 and 10 compare against.

## Rules
- No writes anywhere, no re-authentication, no deploys, no kills of processes this session did not start, no console steps: those are the Owner's; the table names the click.
- Bounded commands only (`timeout N` first), one at a time; no polling. Recommended for any machine: run renders, builds and sweeps with a time bound and one at a time.
- Never print a secret; environment files are never opened or echoed (check 13 lets the script read the token and report names only).
- Numbers only in the table; a check that cannot run reads "not checked: <why>".
