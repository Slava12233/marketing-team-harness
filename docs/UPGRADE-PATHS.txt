# UPGRADE-PATHS.txt: which files an upgrade may write. Read by upgrade.sh and upgrade.ps1 (both read the copy
# inside the NEW release, so a release always brings the list that matches its own files).
#
# Three sections, one path per line; '#' starts a comment.
#   [replace]   harness-owned: overwritten from the release (the old file is backed up first)
#   [add-only]  copied only when the file does not exist in the buyer's copy; an existing file is kept
#   [never]     company-owned or per-machine: never written, even when the release carries the path
#
# Path forms (always forward slashes, relative to the harness folder):
#   dir/          everything under that folder, at any depth
#   path/file     that one file
#   *  ?          any characters / one character inside one path segment (never across a '/')
#   **/           any number of folders (including none)
#   !path         under [never] only: an exception to [never] (the path then follows the other sections)
#
# Precedence: [never] wins over [add-only], which wins over [replace]. A path in no section is left alone and
# shown as "not listed" in the plan: every new harness folder or root file must be added here in the same
# release that introduces it (docs/TEMPLATE-SPEC.md §3 is the file map this list follows).
