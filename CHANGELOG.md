# Changelog

All notable changes to the Marketing Team Harness are recorded in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). A release is an annotated tag `vX.Y.Z` plus the zip that `release.sh` / `release.ps1` builds from it; the release scripts refuse to tag a version that has no `## [X.Y.Z]` heading here.

## [Unreleased]

The product build of 2026-10-26: what a buyer needs to go from a computer without the tools to a configured harness and a first campaign built PAUSED.

### Added

- `.mcp.json` in the repository root: the two connections (`meta-ads`, `fal`) ship with the files. Opening the folder in Claude Code asks to approve them, and `/mcp` then logs in. The typed `claude mcp add` commands stay in the docs as the fallback.
- `bootstrap.ps1` (Windows) and `bootstrap.sh` (macOS; it also runs in Git Bash and on Linux): the buyer's first command. It checks Git, Node.js 20 or newer, Claude Code, a browser for the ad screenshots (reported, never installed) and `.env`, shows one plan block of what is missing and, after one confirmation (Enter), installs all of it: Git and Node.js LTS (winget on Windows, Homebrew on macOS), Claude Code (the official installer), FFmpeg, `playwright-core`, Obsidian and the HyperFrames video plugin from `vendor/hyperframes`; creates `.env` from `.env.example` (never shown); sets Obsidian up for the vault with no click (`memory/tools/obsidian-setup.mjs`); opens the setup progress page; and ends with what remains. `--check` / `-Check` only reports; `--yes` / `-Yes` installs without the question; `--ask` / `-Ask` asks per item. Python is not needed and not installed.
- The HyperFrames video plugin vendored under `vendor/hyperframes/` (Apache-2.0, version 0.8.160, upstream commit `695110e46ba4ec971f5dcfc797ce8bf750e1029d` of https://github.com/heygen-com/hyperframes): its 21 skills unchanged, with a local marketplace manifest and `VENDOR.md`; the bootstrap installs it from there (after checking Node.js 22 or newer and offering FFmpeg), never from GitHub; the renderer comes from npm on first use. Credited in `THIRD-PARTY.md` and pinned under `plugins` in `skills-lock.json`.
- `release.ps1` and `release.sh`, the maintainer's release step: clean working tree (every file under `vendor/` tracked, none hidden by an ignore rule), scrub gate, changelog heading, annotated tag, and a zip in `dist/` built with `git archive`. They never push. This `CHANGELOG.md` goes with them.
- `config/goals.md` and a goals-and-money round in the `/setup` interview: the monthly budget band in the account currency, a target cost per result for each funnel, the first funnel to launch, hard daily, weekly, monthly and per-campaign caps, what success in 30 days means, the appetite for tests, and the review cadence (weekly, in `/next-round`, unless the Owner sets another).
- The Meta console steps as numbered click lists, in `/setup` and in `docs/meta-setup-guide.md`, with Meta's URLs, what you should see, and a live check wherever a read exists.
- The setup progress page: `dashboard/setup-page.mjs` (Node 20+, no dependencies) writes `dashboard/setup.html`, a page the Operator keeps open in a browser beside Claude Code during setup. It shows a progress bar, the next step and the thirteen setup chapters (from "Before you start" to the routine), each step marked done, to do, in progress, n/a or "your turn" for the Owner's clicks in Meta, with the Meta screen to open. The statuses come from `checklist.md`, the console steps of `config/accounts.md`, `.mcp.json`, whether `.env` exists (it is never opened), the `config/` placeholders, the first flight plan and `dashboard/state.json`; where the files say nothing, the wizard's marks in `dashboard/setup-progress.json` fill in (the files always win). It works offline, reloads itself every 5 seconds, and comes in English and Hebrew (right to left) with a toggle, defaulting to the chat language in `config/operator.md`. The bootstrap opens it at the end of a real run (never under `--check` / `-Check`), `/setup` opens it and regenerates it after every step, and `/health`, `/morning` and `/sync` regenerate it. It shows names and public ids only, never a secret. Both generated files are git-ignored; `dashboard/setup-page.test.mjs` is its smoke test.
- `LICENSE`.
- The memory vault, `memory/`: the harness's memory as linked Markdown notes that open in Obsidian, under a written contract (`memory/README.md`: the folders, the frontmatter every note carries, who writes what, the caps). `HOME` is the Owner's start note and the Inbox (`memory/inbox/`) is where the Owner leaves questions and instructions between sessions; both are written in the chat language from `config/operator.md`. Bases dashboards in `memory/bases/` (campaigns, decisions, experiments, learnings, open items, reports, sessions). The generators in `memory/tools/` (`build-hot.mjs` writes `HOT.md`, `INDEX.md`, HOME's generated block and `dashboard/state.json`; `build-capabilities.mjs` writes the capability map) and the lint (`lint.mjs`) keep the vault consistent. Two hooks in `.claude/hooks/`: SessionStart injects `HOT.md` into every new session, and PreCompact writes a checkpoint into the day's session note before a compaction; they ship turned on in `.claude/settings.json` (Claude Code asks once to trust the folder), and `docs/hooks-paste-block.md` holds the block to restore if that file is deleted or replaced. `/consolidate` runs the weekly pass that merges duplicates, supersedes stale facts and archives closed items. The six Obsidian skills by kepano (`obsidian-markdown`, `obsidian-bases`, `obsidian-cli`, `json-canvas`, `defuddle`, `knap`; MIT), pinned in `skills-lock.json` and credited in `THIRD-PARTY.md`. The bootstrap installs Obsidian (free, also for commercial use: winget `Obsidian.Obsidian` on Windows, the Homebrew cask on macOS, the download page on Linux) with the other items after its one confirmation, reports the path it finds, and then sets it up with no click (below). The setup progress page gains the chapter "The memory vault (Obsidian)" right after Install: Obsidian installed (the app's own path, else the bootstrap's mark), this folder registered as a vault (Obsidian's global `obsidian.json` lists it), the command line interface on (`"cli": true` in the same file), the hooks in place (`.claude/settings.json` names `session-start.mjs`) and the business note filled (`memory/business/company.md` without a `<fill at /setup>` placeholder); none of them is ever the Owner's click.
- Obsidian with no click and nothing to paste: `memory/tools/obsidian-setup.mjs` (Node 20+, no dependencies) registers the harness folder as a vault in Obsidian's global config (`obsidian.json`), turns on its command line interface there (the key `cli`, verified on Obsidian 1.14.5) and starts the app; `--check` only reports, `--quiet` prints nothing, `--cli-path` prints the CLI binary and `--cli <args>` runs it by full path, so nothing is added to PATH. The bootstrap runs it after its installs (and with `--check` under `-Check` / `--check`, as a report line) and ends with "Obsidian is set up: the vault is registered, the command line interface is on, the app opened on your HOME page"; `/setup` runs it after filling the vault (step 5.5), `/sync` next to the generators, and `/health` check 19 with `--check`. The Owner's only Obsidian action is to use it: HOME and the Inbox. The example company in `examples/acme-fitness/` gains a filled example vault.

### Changed

- Instant-form leads arrive through Meta's own delivery by default (Leads Center, email notifications, CRM integrations); the lead webhook is an advanced path that needs a developer.
- `README.md` and `ONBOARDING.md` rewritten around the bootstrap script, the approve-then-log-in connections and the setup chapters.
- `control-room/`: the money tile reads `money.caps` entries as `{ label, amount, period }` (copied from `config/goals.md` by `/morning` and `/sync`); `health` gained checks 14 (bootstrap) and 15 (money vs caps); the example company gained `config/goals.md`, a Money section in its first-flight plan and a Leads Center checklist row.
- The scrub gate: the backslash spelling of its drive-path term now matches a real Windows path (the earlier spelling, with two backslashes, only matched JSON-escaped paths), and the gate skips `vendor/` (verbatim third-party files, like the third-party skills).
- The memory model. `CLAUDE.md` keeps the rules and loses the facts: account state, campaigns, decisions and learnings move into the vault. The skills and the agents read `HOT.md` and their lane map (`memory/maps/<lane>.md`) before they start. Sub-agents propose (they append to `memory/inbox/proposals.md` and write their own output notes); only the main session writes the canonical notes. `memory.md` is now a pointer to the vault. `/setup` fills the vault's business notes as it writes `config/`. The control-room data file `dashboard/state.json` is generated by `build-hot.mjs` instead of being written by hand.
- `creative-production` and `creatives/tools/render-stills.mjs` install playwright-core with `npm install --no-save --no-package-lock playwright-core`, the same line as the bootstrap, so the repository gains no `package.json`.
